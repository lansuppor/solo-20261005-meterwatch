# meterwatch

建筑能耗监测:本地累计电表读数导入与消耗核查。

需要 Node.js 24,无外部运行依赖。

## 使用

```sh
node app.ts --help                       # 应用名与完整帮助
node app.ts import readings.csv          # 导入 CSV(整批成功或整批拒绝)
node app.ts readings                     # 查询全部读数与消耗
node app.ts readings --device meter-1 \
  --from 2026-01-01T00:00:00Z --to 2026-02-01T00:00:00Z
node app.ts daily \
  --from 2026-01-01T00:00:00Z --to 2026-02-01T00:00:00Z   # 按 UTC 自然日的能耗日报
node app.ts daily --tz America/New_York \
  --from 2026-03-01T00:00:00Z --to 2026-04-01T00:00:00Z   # 按指定 IANA 时区的当地自然日
node app.ts daily --device meter-1 --device meter-2 \
  --from 2026-01-01T00:00:00Z --to 2026-01-02T00:00:00Z   # 只统计指定设备
node app.ts daily --max-interval 3600 \
  --from 2026-01-01T00:00:00Z --to 2026-02-01T00:00:00Z   # 相邻读数间隔超过 3600 秒的区间视为未知

node app.ts rule create --id peak --device meter-1 --threshold 6   # 创建设备告警规则(时区省略为 UTC)
node app.ts rule create --id floor-peak --group floor-1 --threshold 20  # 创建分组告警规则
node app.ts rule create --id ny-peak --device meter-1 --threshold 6 \
  --tz America/New_York                                           # 按指定 IANA 时区的当地日期评估
node app.ts rule create --id gap-peak --device meter-1 --threshold 6 \
  --max-interval 3600                                             # 采样间隔超过 3600 秒的日期不可判定
node app.ts rule list                                   # 查看全部规则(显示目标类型、时区与间隔限制)
node app.ts evaluate --rule peak \
  --from 2026-01-01 --to 2026-02-01                     # 评估连续完整当地日期(按规则时区,设备或分组规则)
node app.ts alerts --rule peak                          # 查询告警历史(只读)
node app.ts alerts --rule peak --from 2026-01-01 --to 2026-01-10
node app.ts ack alert-1                                 # 确认告警

node app.ts group configure --id floor-1 \
  --at 2026-01-01T00:00:00Z --device meter-1 --device meter-2   # 配置分组成员版本
node app.ts group configure --id floor-1 \
  --at 2026-01-15T00:00:00Z --device meter-1                    # 乱序补录/追加版本均可
node app.ts group history --id floor-1                          # 查看成员版本历史(只读)
node app.ts group daily --id floor-1 \
  --from 2026-01-01T00:00:00Z --to 2026-02-01T00:00:00Z         # 分组能耗日报(只读)
node app.ts group daily --id floor-1 --tz Asia/Shanghai \
  --from 2026-01-01T00:00:00Z --to 2026-02-01T00:00:00Z         # 按指定时区的当地自然日
node app.ts group daily --id floor-1 --max-interval 3600 \
  --from 2026-01-01T00:00:00Z --to 2026-02-01T00:00:00Z         # 成员间隔过长的时段记为未知

node app.ts group schedule-report --id floor-1 --schedule weekly.txt \
  --from 2026-01-01T00:00:00Z --to 2026-02-01T00:00:00Z         # 按每周运行时间表分运行/非运行时段核查(只读)
node app.ts group schedule-report --id floor-1 --schedule weekly.txt \
  --tz Asia/Shanghai --max-interval 3600 \
  --from 2026-01-01T00:00:00+08:00 --to 2026-02-01T00:00:00+08:00
                                                                # 时间表按指定时区解释,间隔过长记为未知

node app.ts correct --request REQ-2026-001 \
  --item --device meter-1 --at 2026-01-02T00:00:00Z --expect 110.000 --set 115.500 \
  --item --device meter-2 --at 2026-01-02T08:00:00+08:00 --expect 9007199254741.991 --set 9007199254741.991
                                                          # 批量修正已存读数(整批成功或整批拒绝)
node app.ts undo --request UNDO-2026-001 --target REQ-2026-001
                                                          # 整批撤销一次已成功修正
node app.ts corrections                                   # 查看修正与撤销历史(只读)

node app.ts backup /tmp/meterwatch-snapshot.json          # 导出全库快照(须位于数据目录之外)
node app.ts restore /tmp/meterwatch-snapshot.json         # 从快照整库恢复(三个业务存储一次提交)
```

## 分日时区(--tz)

`daily` 与 `group daily` 接受可选的 `--tz <IANA 时区名>`(如
`Asia/Shanghai`、`America/New_York`),按该时区的当地自然日划分日报;
省略时按 UTC。时区只决定分日,不重新解释输入时刻或已存读数;设备筛选、
分组选择与必填起止时刻(起点含、终点不含)沿用原有方式。

日界线按实际时刻的当地日期归属计算,不用固定 86400 秒或全年固定偏移
推算:夏令时前拨跳过的当天更短(跳过的小时不存在,不补为未知),回拨
当天更长(重复小时按各自实际时刻完整计入)——例如 America/New_York 的
2026-03-08 为 82800 秒、2026-11-01 为 90000 秒,覆盖分类以这些实际
时长为准。同一当地日期的不连续时段合并统计、分别列出;没有实际时段的
当地日期不生成日报。每天标明所用时区与实际统计的各 UTC 时段,
有效/异常/未知秒数之和等于这些时段的总秒数;日界线不重置分摊起点,
拆开查询再相加与整段一致。未知时区名为参数错误,返回 2。

## 采样间隔限制(--max-interval)

`daily`、`group daily` 与 `rule create` 接受可选的 `--max-interval <秒>`
(正整数秒数),限制可信的最大采样间隔,避免把长时间缺采误当成可信能耗;
省略均表示无上限,继续采用原计算口径。非法取值(非正整数)为参数错误,
返回 2。查询设置只影响本次结果,不写入数据;规则设置在创建后固定。

限制按完整已存时序中相邻读数的实际时间差判断,等于限制仍可信。非下降
区间超过限制时,整个区间视为未知,不分摊消耗;不能因查询范围、当地日
界线或成员切换把它裁短而变成可信区间。下降区间仍为异常,即使也超过
限制;首末读数之外和孤立读数时段仍为未知,不外推。其他有效区间继续以
原区间起点累计比例向下取整求片段差,BigInt 精确计算,kWh 固定三位小数。

分组按当时生效成员分别判断:任一成员下降优先记异常,否则任一成员未知
便记未知,全部可信才计成员消耗之和;首个成员版本前仍为未知。日报和
告警的当前计算显示采用的限制、有效/异常/未知秒数,并区分过长间隔造成
的未知覆盖(gap),指出相关设备及原始相邻读数时刻;分组的过长间隔未知
秒数只在最终未知时段内按实际时间计并集,不叠加成员秒数,三类覆盖仍
合计为实际统计时长。命名时区的实际自然日、估算标记与不完整提示保持
不变。

规则的间隔限制与标识、目标、阈值、时区一起参与重试比较:同标识同参数
(含同限制)重试成功且不新增,任一不同即报冲突。限制随规则在 `rule
list` 中显示,重启后保留,备份恢复完整保留;旧规则和旧快照未设置限制
时按无上限使用,已存非法限制按损坏数据拒绝,不能悄悄忽略。仅全天有效
覆盖的日期才与每日阈值比较,未知(含过长间隔)或异常日期不触发也不
恢复。补导历史读数使相邻间隔缩短后,查询立即按新时序重算,但检测状态
只由显式 `evaluate` 更新。

## 读数修正(correct / corrections)

`correct` 一次提交指定非空请求标识(`--request`,去首尾空白、区分大小写,
在数据目录内唯一)及至少一个 `--item` 修正项;每项用 `--device`、`--at`、
`--expect`、`--set` 给出设备、实际时刻、预期原读数和替换读数(校验口径与
CSV 相同)。只修改已有读数的累计值,不新增或删除读数;同批同一读数身份
(设备+实际时刻)只允许一项;替换值可等于原值,仍须核验预期原值。

首次提交逐项把预期原值与操作前已存值精确比较,全部匹配才整体替换,成功
报告请求标识与实际改变数;任一项身份不存在或原值不符均指出原因、整批
拒绝,不改变其他项,也不占用请求标识(失败后可修改内容用同一标识重新
提交)。读数替换与请求成功记录在同一 `readings.json` 中原子持久化,写入
失败保留操作前全部状态,重启后两者一致。

同标识、同修正内容重放直接返回原成功结果,不重新校验当前读数、不再次
替换——即使这些读数随后被另一个请求再次修正,重放也不覆盖后来的值。
修正项顺序、等价时区写法(如 `Z` 与 `+08:00`)及等价十进制写法(如
`115.5` 与 `115.500`)不影响内容等价性;同标识异内容报冲突且保持状态。
`corrections` 按成功提交顺序显示各请求及各项设备、时刻、原值和替换值,
只读不写入。

修正后 `readings`、`daily`、`group daily` 与 `alerts` 的当前消耗按新相邻
区间重算(区间归属、累计比例分摊、下降及未知覆盖口径不变);分组成员、
规则和告警记录不变,检测状态仍需显式 `evaluate` 更新,旧确认、触发和
恢复时的消耗及事件顺序保留。后续 `import` 按当前(修正后)读数判重与
冲突,并保留修正历史和重放识别能力;旧版无修正历史的读数文件无需手工
迁移即可使用。修正所用存储损坏、不可读或读数存在全库重复身份时报错
返回 1,绝不当作空库。

## 修正撤销(undo)

`undo` 一次提交指定非空撤销请求标识(`--request`,去首尾空白、区分大小写)
及目标修正请求标识(`--target`),整批撤销一次已成功修正,不允许挑选
部分项;目标只能是成功修正,不能是撤销请求,未知或已撤销目标报错。
撤销与修正请求在数据目录内共用唯一标识空间,成功标识绑定操作类型和
内容。

首次撤销只恢复目标中实际改变过的读数,将其还原为该修正记录的原值,
不新增或删除读数。每个待恢复身份必须存在、当前值精确等于原替换值,
且没有后来尚未撤销、实际改变过该读数的修正;后来改回相同数值也不能
绕过来源检查,相关后续修正先撤销后,可再撤销较早请求。原修正中的
同值项不恢复、不阻塞其他请求;全部为同值项的目标仍可成功撤销,恢复
数为零。任一项不满足条件须指出身份和原因,整次拒绝,不占用撤销标识
(失败后可修改内容用同一标识重新提交)。

成功报告撤销请求、目标和恢复数,保留原修正内容并标记已撤销;读数恢复、
目标状态和撤销成功记录在同一 `readings.json` 中原子持久化,任何拒绝或
写入失败均保留操作前全部状态,重启后状态与来源判断一致。同撤销标识、
同目标重放返回原成功结果,不重新核验撤销资格、不重复恢复或新增历史;
同标识异内容或跨操作类型复用标识均报冲突且保持状态。已撤销修正的原
请求重放仍返回原成功结果,不重新应用修正或新增历史。

`corrections` 按成功提交顺序显示各修正请求及各项设备、时刻、原值和
替换值(已撤销的带标记),另按成功发生顺序显示撤销请求与目标关系,
只读不写入。撤销后 `readings`、`daily`、`group daily` 与 `alerts` 按
当前读数重算,口径不变;撤销不改成员、规则或告警历史,检测状态仍需
显式 `evaluate` 更新,旧确认和事件消耗保留。后续 `import` 和 `correct`
均保留撤销状态、历史及重放识别能力;旧版无撤销记录的文件可直接使用,
原修正视为未撤销。修正、撤销及 `corrections` 查询均检查所用存储,损坏、
不可读或全库重复读数身份时报错返回 1,重放也不能绕过。

## 分组成员版本与分组日报

分组以首次 `group configure` 建立,标识非空唯一(去首尾空白、区分大小写)。
每次配置用 `--at` 指定生效时刻(含,秒精度 ISO8601 带 `Z` 或数字时区偏移),
用 `--device` 给出一整套已有设备(至少一个,可重复;同设备重复列出只算
一次,成员顺序不影响等价性,设备可属于多个分组)。版本从生效时刻起生效,
直到下一版本接替;允许乱序补录历史版本。同组同一实际生效时刻、同成员
集合重试成功且不新增,异成员集合报冲突;未知设备报错。配置整次成功或不
提交,不改读数、规则和告警;导入也不改配置。`group history` 按生效时刻
列出全部版本。配置存于数据目录的 `groups.json`,退出重启后版本与成员不
丢失。

`group daily` 的 `--from`(含)与 `--to`(不含)必填且起点必须更早,按
UTC 自然日切分,首尾日期只统计重叠部分。按当时生效成员计算,不把最新
成员套用到历史;首个版本生效前记为未知。各设备使用完整已存时序,区间
两端读数即使在查询范围外也参与;成员切换不需要恰好有读数,首条读数之
前、末条之后及孤立读数时段为未知,不外推。

每个时段只有全部生效成员均处于非下降读数区间时才是有效覆盖,并计入成员
消耗之和;任一成员下降则为异常覆盖,否则任一成员未知则为未知覆盖。异常
与未知时段不计任何成员消耗,不以缺失设备为零补齐。覆盖秒数按分组实际
时间计算,不累加成员秒数。各设备片段仍以原读数区间起点累计比例向下
取整,两端累计量之差为消耗;日界线、查询边界与成员切换均不重置分摊
起点,拆开查询相加结果一致。全程 BigInt 精确计算,kWh 固定三位小数。

每天显示生效成员及其时段、估算消耗与有效/异常/未知秒数,三者之和等于
当天查询时长;有异常或未知标为不完整(INCOMPLETE),无有效覆盖显示无法
计算,有效零增长显示零,并汇总有效消耗。`group daily` 接受可选的
`--max-interval <秒>`(正整数,省略为无上限,只影响本次查询):成员的
非下降相邻区间超过限制即把整个区间记为未知,分组的过长间隔未知秒数
(gap)只在最终未知时段内按实际时间计并集并单独显示(详见"采样间隔
限制"一节)。日报与历史只读;读取读数时拒绝同设备同一实际时刻的多条
存储记录。

## 运行/非运行时段报表(group schedule-report)

`group schedule-report` 按本地每周运行时间表把查询范围分为**运行**与
**非运行**两类时段,分别核查分组能耗(只读,用于核查停运消耗)。
`--id` 指定已有分组,`--schedule` 指定本地时间表文件,`--from`(含)与
`--to`(不含)必填且起点必须更早(秒精度 ISO8601,带 `Z` 或数字时区
偏移);`--tz` 可选(IANA 时区,默认 UTC),**只解释时间表**,不重新解释
起止时刻或已存读数;`--max-interval` 可选(正整数秒,默认无上限,只
影响本次查询,口径见"采样间隔限制"一节)。

时间表文件为文本格式,每行一个运行窗口:

```
# <星期> <开始 HH:mm> <结束 HH:mm>(空行与 # 之后的注释忽略)
mon 08:00 18:00
tue 08:00 18:00
fri 08:00 24:00
sun 22:00 02:00    # 结束早于开始:跨至周一 02:00(不含)
```

- 星期为 `mon tue wed thu fri sat sun`(不区分大小写)
- 开始限 `00:00`-`23:59`,结束另可 `24:00`;同值起止拒绝
- 结束早于开始即跨至下一日,尾段沿用开始日规则,周日可跨至周一
- 窗口起点含、终点不含,重叠或重复取并集;零个窗口(空表)表示全部非运行
- 窗口按实际时刻的当地日期与墙钟分类,每秒只属一类:夏令时跳过时段不
  虚构覆盖,回拨重复时段各自分类,不套固定偏移或日长

能耗口径与 `group daily` 相同:按当时生效成员与完整读数时序,全部成员
可信才累加消耗,任一成员下降优先为异常,否则任一成员未知为未知;首个
版本生效前、读数首末之外与孤立读数未知,不外推;采样限制按原始相邻
区间判断,裁切不使过长区间可信,等于限制仍可信;有效片段取原区间起点
累计比例向下取整的两端差,切分不重置起点,BigInt 精确计算,kWh 固定
三位小数。

两类分别显示实际 UTC 时段、估算消耗与有效/异常/未知秒数(采用限制时
另显示过长间隔未知秒数 gap 及相关设备与原始相邻读数时刻);覆盖按时间
计,不叠加成员秒数,两类覆盖合计等于查询时长,消耗合计等于同范围、同
限制的分组日报,拆开查询相加一致。无有效覆盖显示无法计算,有效零增长
显示零,有未知或异常标 INCOMPLETE。报表不改写时间表或业务存储、不自动
评估,修正撤销后重查使用当前读数;启动沿用目录排他与中断恢复。成功
(含不可计算结果)返回 0;非法时间表、参数或未知时区返回 2;时间表文件
不可读、未知分组、所用存储损坏或全库重复读数身份返回 1,指出原因,不
输出部分报表。

## 每日能耗阈值告警

规则由使用者指定非空标识,该标识在设备规则与分组规则间统一唯一(去首尾
空白、区分大小写)。每条规则用 `--device <设备>` 或 `--group <分组>` 恰好
之一绑定目标,并指定非负、最多三位小数的 kWh 阈值;目标、阈值、时区与
采样间隔限制创建后固定。设备必须已有存储读数,分组必须已经
`group configure` 建立;设备与分组即使同名也是不同目标,`rule list` 与
`alerts` 历史都显示目标类型(`device=...` / `group=...`)、时区与间隔
限制。分组规则绑定的是分组标识,不冻结创建时的成员。相同标识、同目标
类型、同目标标识、等价阈值、同时区及同间隔限制重试成功且不重复创建,
任一不同即报冲突。

`rule create` 接受可选的 `--tz <IANA 时区名>`(如 `Asia/Shanghai`、
`America/New_York`),按该时区的当地日期评估;省略时按 UTC,与显式 `UTC`
等价。时区按运行环境解析后的规范名称存储与比较(同一时区的不同写法视为
相同),创建后固定;未知时区名为参数错误,返回 2。`rule create` 同时接受
可选的 `--max-interval <秒>`(正整数),限制可信的最大采样间隔,省略为
无上限,创建后固定(口径见"采样间隔限制"一节)。规则时区、间隔限制与
告警历史重启后保留;没有时区的旧规则按 UTC 使用,未设置限制的旧规则与
旧快照按无上限使用,原告警标识、日期、状态和事件顺序保留;存储内非法
时区或非法间隔限制按损坏数据处理,不能回退或忽略。

`evaluate` 与 `alerts` 的 `--from`/`--to` 为 `YYYY-MM-DD` 的当地日期
(按规则时区解释),起日含、止日不含,起日必须更早。每个日期统计归属该
日期的全部实际 UTC 时段,不把当地午夜简单套用固定偏移:夏令时前拨的短日
不补未知(跳过的小时不存在),回拨的重复小时按各自实际时刻完整计入;日期
回退产生的不连续时段合并为同一天,一次评估只作一次判定;整日被跳过的日期
标明跳过,不判定、不创建也不恢复告警。设备规则的评估口径与 `daily` 相同
(完整时序、均匀分摊、累计比例向下取整、BigInt 精确汇总);分组规则与
`group daily` 的联合覆盖口径相同:每天按当时生效的成员版本切分(允许日内
切换),首个版本生效前为未知,任一成员下降为异常,否则任一成员未知为未知;
成员切换不重置各设备原读数区间的分摊起点。仅全天有效覆盖的日期可判定,
消耗严格大于阈值才超限,等于阈值视为正常;有未知或下降覆盖的日期不可判定,
不触发也不恢复;零增长是有效数据。

每条规则的每个日期独立跟踪:首次判定超限创建带全局唯一标识的未确认告警
(设备与分组规则共用同一编号空间,新标识不得与旧告警冲突),重复超限保留
原标识且不新增事件;后续完整评估正常才记录恢复;恢复后再超限创建新的
未确认告警,旧记录保留,原确认不转移给新告警。`ack` 按告警标识确认,
已恢复告警也可确认;重复确认成功且不重复记事,确认不改变超限或恢复状态。
`alerts` 按规则和当地日期升序展示当前计算的消耗或不可判定原因、各日期的
实际 UTC 时段及有效/异常/未知秒数(采用间隔限制时另显示采用的限制、过长
间隔造成的未知秒数及相关设备与原始相邻读数时刻)、各次告警的标识、检测
状态、确认状态及按发生顺序排列的触发/恢复/确认事件;触发与恢复时的消耗
为评估当时记录,不随后续数据变化改写;省略日期范围时展示有告警记录的全部
日期。

导入读数或补录成员版本都不自动评估,显式重评才会更新检测状态;历史查询
只读,不会隐式恢复。批量日期评估要么全部提交要么不提交;创建、评估、
确认任一失败都保留操作前全部状态。读取读数时拒绝全库重复身份(同一设备
同一实际时刻的多条存储记录),包括不属于任何分组的设备。

规则与历史存于数据目录的 `alerts.json`,旧版只含 `device` 字段、无时区
字段的设备规则、告警标识、确认状态与事件顺序无需手工转换即可继续使用。

## 备份与恢复(backup / restore)

`backup <快照文件>` 把当前数据目录(`$METERWATCH_DATA_DIR`,默认
`~/.meterwatch`)的三个业务存储——`readings.json`(读数与修正、撤销历史)、
`alerts.json`(告警规则与历史)、`groups.json`(分组成员版本)——连同后续
编号所需状态(下一告警编号、下一事件序号)完整导出为一个快照文件。快照完整
保留累计读数、修正与撤销请求及顺序、分组成员版本、设备和分组规则及时区与
采样间隔限制、告警标识、检测与确认状态、事件顺序和当时消耗;毫千瓦时为
十进制字符串,任意大数精确保留。旧版以安全整数数值保存、无修正撤销历史、
无时区规则或未设置间隔限制的存储可直接备份,缺失的存储文件按对应空状态
处理。

快照文件必须位于数据目录之外(否则为参数错误,返回 2);已存在的输出文件
拒绝覆盖。快照带格式标识、格式版本与负载的 SHA-256 完整性校验;备份只读取
业务数据,不改写,失败时不留下可被当作成功快照的输出。

`restore <快照文件>` 从快照整库恢复,不解析当前库,可用于当前存储已损坏的
目录。快照的版本不受支持、内容被截断、校验不符或不可读时不开始替换。备份与
恢复都校验三个业务存储的结构和关联:全库重复读数身份、修正项引用缺失读数、
撤销引用缺失修正、分组成员或规则目标不存在、告警引用缺失规则——任一问题
指出原因并拒绝。

恢复为整库替换,三个业务存储作为一次提交:成功后业务状态完全等于快照,
快照为空的部分清除原数据,快照之后新增的读数、请求和告警不保留;只替换
三个业务存储文件,目录内其他文件保持不变;不自动评估或重新生成历史,成功
时报告恢复的数据及历史数量。读写或重命名失败返回 1,并回退到恢复前的文件
内容与存在状态。

### 中断续接(崩溃恢复)

恢复用数据目录内的 `restore.journal` 记录阶段,三个业务存储的新内容先写到
`*.restore-new`,提交时把原文件换名为 `*.restore-old` 再换入新内容:

- `preparing`(准备):新内容已写、尚未换名。此阶段被中断,再次启动可收敛
  为**完整旧库或完整快照**(优先前滚快照;前滚受阻则回滚旧库)。
- `committing`(文件替换):换名可能已完成任意步。此阶段被中断只能**继续
  前滚为完整快照**;若前滚无法完成,返回 1 并保留全部材料,不自行改向。
- `rolling-back`(失败回滚):一旦进入此阶段就**只能继续还原完整旧库**,
  不能再改为前滚;回滚是幂等的,自恢复再次中断仍可续接。已还原到原位的
  旧文件不会被误删;恢复前原本缺失的业务文件回滚后**恢复为缺失**,不会把
  事务造成的缺文件误当成空库而补写。
- `done`:快照已落地,仅完成日志/备份清理。

任一命令(**包括无参数、`--help`/`-h` 以及参数非法的入口**)再次启动时,
都先取得数据目录操作权、处理完未完成恢复,然后才执行查询或写入。无法可靠
判定或完成一致恢复时返回 1:不输出正常业务结果、不做业务写入,也不销毁仍
可用于恢复的材料;排除底层读写问题后再运行任意命令即可续接。

### 目录操作权(排他锁)

每个命令从取得目录操作权起,先协调恢复再读写业务存储。操作权是按数据目录
隔离的排他锁(数据目录内的 `meterwatch.lock`,进程退出即失效):

- 同目录被其他**存活**进程占用时,明确拒绝并返回 1,不读写业务存储,也不
  清理对方的事务材料;
- 持锁进程退出后,下一个命令自动接管(包括接管其未完成的恢复),不同数据
  目录之间互不阻塞;
- 备份、恢复以及启动自恢复期间,其他命令同样受此限制。

恢复并重启后,查询按快照读数及成员计算,旧告警状态、确认和事件消耗不被
改写;原修正与撤销请求重放返回原结果,不再次应用,未撤销修正的来源阻塞
仍有效;后续导入、修正、撤销、评估和确认继续可用,新告警及事件不与旧
标识或序号冲突。

### 故障处理

- 报 `locked by another live meterwatch process`:等待占用进程结束;若确认
  该进程已退出却仍被拒(例如锁文件中进程号不可读),删除数据目录内残留的
  `meterwatch.lock` 后重试。
- 报 `cannot complete interrupted restore ... materials were kept`:说明日志、
  `*.restore-old`、`*.restore-new` 都保留在数据目录中。先排除磁盘只读、
  权限或空间问题,再运行**任意**命令完成续接;不要手工删改这些文件。
- 报恢复日志不可读或无效:目录已无法自动判定一致性,需用已知完好的快照
  重新 `restore`,不要在可能处于混合状态的目录上直接继续业务操作。
- 快照校验失败(版本不受支持、内容截断、校验不符)时不会开始任何替换,
  当前库保持原样。

## CSV 格式

表头固定为 `device,time,reading`,每行一条读数:

- `device`:设备标识,区分大小写,首尾空白忽略,去空白后不能为空
- `time`:秒精度 ISO8601,带 `Z` 或数字时区偏移(如 `+08:00`),必须是真实日期
- `reading`:累计电表读数(kWh),非负,最多三位小数

支持标准双引号字段与 `""` 转义。同一设备同一实际时刻(不同时区偏移
表示同一时刻视为相同)重复且数值相同记为重复并跳过;数值不同视为冲突,
拒绝整批。任一行格式错误同样拒绝整批,不留下部分数据。

## 查询说明

- `--from` 含、`--to` 不含,省略表示不限;起点不早于终点时拒绝查询
- 结果按设备及实际时刻排序;区间由同设备紧邻前驱构成(前驱取自完整
  已存时序,可能在范围之外),区间归属结束时刻
- 无前驱时标明无法计算;累计值下降显示下降异常且不计入汇总
- 时间以 UTC 显示;数值以毫千瓦时 BigInt 精确运算,无浮点尾差,
  不受 Number 安全整数范围限制

## 日报(daily)

`daily` 按 UTC 自然日核查能耗,只读、不写入数据。`--from`(含)与
`--to`(不含)必填且起点必须早于终点;`--device` 可重复指定设备,省略时
统计库内全部设备;`--max-interval <秒>` 可选(正整数,省略为无上限,
只影响本次查询,口径见"采样间隔限制"一节)。日期按 UTC 零点划分,首尾
日期只统计与查询范围重叠的部分。

估算口径:

- 区间由每个设备完整时序的相邻读数构成,两端读数即使在查询范围外也
  参与;范围内没有读数但被有效区间覆盖时仍得到结果
- 非下降区间把累计值之差按持续时间均匀分摊,标为估算:以千分之一 kWh
  为单位,从区间起点累计到切点(查询边界与日界线)向下取整,片段消耗为
  两端累计量之差;完整区间的分摊总量等于原差值,同一区间拆开查询再相加
  结果一致;中间乘积与汇总用 BigInt 精确计算,显示固定三位小数
- 下降区间不分摊消耗,记为异常覆盖;其后的区间仍从下降后的读数计算
- 首条读数之前、末条之后及孤立读数时段为未知,不外推
- 采用 `--max-interval` 时,非下降相邻区间的实际时间差超过限制即把整个
  区间记为未知(等于限制仍可信;下降区间即使超过限制仍为异常),并按
  设备列出过长区间的原始相邻读数时刻

每天输出估算消耗与有效/异常/未知覆盖秒数,三者之和等于该天实际查询
时长;采用间隔限制时另显示采用的限制与过长间隔造成的未知秒数(gap);
存在未知或异常覆盖时日报标记为不完整(INCOMPLETE)。没有有效覆盖
时消耗显示无法计算,有效零增长显示零;每台设备汇总已计算的每日消耗。
同设备同一实际时刻存在多条存储记录时报错并返回 1。

## 大数值与旧数据兼容

读数与阈值以毫千瓦时(千分之一 kWh)的 BigInt 表示,解析、求差、分摊、
汇总、比较、保存和显示全程精确,输出固定三位小数,不使用科学计数法。
输入可超出 Number 安全整数范围,例如:

```sh
# 三个 9007199254740.991 kWh 的有效区间合计 27021597764222.973 kWh
node app.ts import big.csv          # reading 列直接写十进制大数即可
node app.ts rule create --id peak --device meter-1 --threshold 9007199254740.990
```

旧版 `readings.json` / `alerts.json` 中以 JSON 数值保存的安全整数读数与
阈值无需手工转换,可直接与新导入的大数值共同计算;新版文件以十进制字符
串保存毫千瓦时。数值型毫千瓦时若已超出安全整数范围(JSON 解析时精度
已丢失),按损坏数据拒绝,不猜测原值。

## 数据位置

`$METERWATCH_DATA_DIR/readings.json`,默认 `~/.meterwatch/readings.json`;
读数与修正、撤销历史同文件保存(旧版无修正与撤销历史的文件可直接使用);
告警规则与历史存于同目录的 `alerts.json`,分组配置存于同目录的
`groups.json`,三者相互独立,导入与修正都不会触碰告警状态与分组配置。
退出后再次启动仍可查询。

退出码:0 成功;1 数据或读写错误;2 参数错误。
