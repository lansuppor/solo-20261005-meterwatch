# meterwatch

建筑能耗监测:本地累计电表读数导入与消耗核查。

需要 Node.js 24,无外部运行依赖。

## 使用

```sh
node app.ts --help                       # 应用名与完整帮助
node app.ts import readings.csv          # 导入 CSV(整批成功或整批拒绝)
node app.ts readings                     # 查询全部读数与消耗
node app.ts readings --device meter-1 \
  --from 2026-01-01T00:00:00Z --to 2026-02-01T00:00:00Z
node app.ts daily \
  --from 2026-01-01T00:00:00Z --to 2026-02-01T00:00:00Z   # 按 UTC 自然日的能耗日报
node app.ts daily --device meter-1 --device meter-2 \
  --from 2026-01-01T00:00:00Z --to 2026-01-02T00:00:00Z   # 只统计指定设备

node app.ts rule create --id peak --device meter-1 --threshold 6   # 创建设备告警规则
node app.ts rule create --id floor-peak --group floor-1 --threshold 20  # 创建分组告警规则
node app.ts rule list                                   # 查看全部规则(显示目标类型)
node app.ts evaluate --rule peak \
  --from 2026-01-01 --to 2026-02-01                     # 评估连续完整 UTC 日期(设备或分组规则)
node app.ts alerts --rule peak                          # 查询告警历史(只读)
node app.ts alerts --rule peak --from 2026-01-01 --to 2026-01-10
node app.ts ack alert-1                                 # 确认告警

node app.ts group configure --id floor-1 \
  --at 2026-01-01T00:00:00Z --device meter-1 --device meter-2   # 配置分组成员版本
node app.ts group configure --id floor-1 \
  --at 2026-01-15T00:00:00Z --device meter-1                    # 乱序补录/追加版本均可
node app.ts group history --id floor-1                          # 查看成员版本历史(只读)
node app.ts group daily --id floor-1 \
  --from 2026-01-01T00:00:00Z --to 2026-02-01T00:00:00Z         # 分组能耗日报(只读)

node app.ts correct --request fix-2026-01 \
  --fix meter-1 2026-01-02T00:00:00Z 200.5 210.250 \
  --fix meter-2 2026-01-02T08:00:00+08:00 9007199254741.991 9007199254742.000
                                                  # 批量修正已存读数(整批成功或整批拒绝)
node app.ts correct history                       # 按成功提交顺序查看修正历史(只读)
```

## 读数修正(correct)

`correct` 一次提交指定非空请求标识(`--request`,去首尾空白、区分大小写,
在当前数据目录内唯一)与至少一项 `--fix <设备> <时刻> <预期原读数> <替换读数>`。
每项修正只修改一条已有读数的累计值,不新增或删除读数;读数身份为
(设备, 实际时刻),与请求标识相互独立,同批同一身份只允许一项。设备标识
去首尾空白、区分大小写;时刻为秒精度 ISO8601 带 `Z` 或数字时区偏移;两个
读数均为非负、最多三位小数的 kWh,任意大的十进制值精确处理。

首次提交把每项预期原值与操作前已存值精确比较,全部匹配才整体替换;替换值
可以等于原值,但仍须核验预期原值。任一项身份不存在或原值不符都明确指出
原因,整批拒绝,不改变其他项,也不占用请求标识(失败后同标识仍可用于
修改后的内容)。成功报告请求标识与实际改变数(替换值不同于操作前已存值的
项数)。读数替换与请求成功记录同次原子写入 `readings.json`,写入失败保留
操作前全部状态,重启后两者一致;存储损坏、不可读或读数存在全库重复身份
(同一设备同一实际时刻多条记录)时报错,绝不当作空库。

同标识、同修正内容重放直接返回原成功结果:不重新校验当前读数、不再次
替换、不新增历史,即使随后另一个请求再次修正了这些读数,重放也不覆盖
后来的值。修正项顺序、等价时区写法(如 `Z` 与 `+08:00` 表示同一时刻)及
等价十进制写法(如 `200.5` 与 `200.500`)不影响内容等价性;同标识异内容
报冲突且保持状态。`correct history` 按成功提交顺序显示各请求及各项设备、
时刻、原值与替换值,只读不写入。

修正后 `readings`、`daily`、`group daily` 与 `alerts` 的当前消耗按新相邻
区间重算,区间归属、累计比例分摊、下降与未知覆盖口径不变。修正不改分组
成员、规则与告警记录;检测状态仍需显式 `evaluate` 更新,旧确认、触发和
恢复时的消耗及事件顺序保留。后续 `import` 按当前(修正后)读数判重与
冲突,并保留修正历史与重放识别能力;旧版没有 `corrections` 字段的读数
文件无需手工迁移即可使用。

## 分组成员版本与分组日报

分组以首次 `group configure` 建立,标识非空唯一(去首尾空白、区分大小写)。
每次配置用 `--at` 指定生效时刻(含,秒精度 ISO8601 带 `Z` 或数字时区偏移),
用 `--device` 给出一整套已有设备(至少一个,可重复;同设备重复列出只算
一次,成员顺序不影响等价性,设备可属于多个分组)。版本从生效时刻起生效,
直到下一版本接替;允许乱序补录历史版本。同组同一实际生效时刻、同成员
集合重试成功且不新增,异成员集合报冲突;未知设备报错。配置整次成功或不
提交,不改读数、规则和告警;导入也不改配置。`group history` 按生效时刻
列出全部版本。配置存于数据目录的 `groups.json`,退出重启后版本与成员不
丢失。

`group daily` 的 `--from`(含)与 `--to`(不含)必填且起点必须更早,按
UTC 自然日切分,首尾日期只统计重叠部分。按当时生效成员计算,不把最新
成员套用到历史;首个版本生效前记为未知。各设备使用完整已存时序,区间
两端读数即使在查询范围外也参与;成员切换不需要恰好有读数,首条读数之
前、末条之后及孤立读数时段为未知,不外推。

每个时段只有全部生效成员均处于非下降读数区间时才是有效覆盖,并计入成员
消耗之和;任一成员下降则为异常覆盖,否则任一成员未知则为未知覆盖。异常
与未知时段不计任何成员消耗,不以缺失设备为零补齐。覆盖秒数按分组实际
时间计算,不累加成员秒数。各设备片段仍以原读数区间起点累计比例向下
取整,两端累计量之差为消耗;日界线、查询边界与成员切换均不重置分摊
起点,拆开查询相加结果一致。全程 BigInt 精确计算,kWh 固定三位小数。

每天显示生效成员及其时段、估算消耗与有效/异常/未知秒数,三者之和等于
当天查询时长;有异常或未知标为不完整(INCOMPLETE),无有效覆盖显示无法
计算,有效零增长显示零,并汇总有效消耗。日报与历史只读;读取读数时
拒绝同设备同一实际时刻的多条存储记录。

## 每日能耗阈值告警

规则由使用者指定非空标识,该标识在设备规则与分组规则间统一唯一(去首尾
空白、区分大小写)。每条规则用 `--device <设备>` 或 `--group <分组>` 恰好
之一绑定目标,并指定非负、最多三位小数的 kWh 阈值;目标与阈值创建后固定。
设备必须已有存储读数,分组必须已经 `group configure` 建立;设备与分组即使
同名也是不同目标,`rule list` 与 `alerts` 历史都显示目标类型
(`device=...` / `group=...`)。分组规则绑定的是分组标识,不冻结创建时的
成员。相同标识、同目标类型、同目标标识及等价阈值重试成功且不重复创建,
任一不同即报冲突。

`evaluate` 的 `--from`/`--to` 为 `YYYY-MM-DD` 的 UTC 日期,起日含、止日
不含,起日必须更早。设备规则的评估口径与 `daily` 相同(完整时序、均匀
分摊、累计比例向下取整、BigInt 精确汇总);分组规则与 `group daily` 的
联合覆盖口径相同:每天按当时生效的成员版本切分(允许日内切换),首个版本
生效前为未知,任一成员下降为异常,否则任一成员未知为未知;成员切换不
重置各设备原读数区间的分摊起点。仅全天有效覆盖的日期可判定,消耗严格
大于阈值才超限,等于阈值视为正常;有未知或下降覆盖的日期不可判定,不
触发也不恢复;零增长是有效数据。

每条规则的每个日期独立跟踪:首次判定超限创建带全局唯一标识的未确认告警
(设备与分组规则共用同一编号空间,新标识不得与旧告警冲突),重复超限保留
原标识且不新增事件;后续完整评估正常才记录恢复;恢复后再超限创建新的
未确认告警,旧记录保留,原确认不转移给新告警。`ack` 按告警标识确认,
已恢复告警也可确认;重复确认成功且不重复记事,确认不改变超限或恢复状态。
`alerts` 按规则和日期展示当前计算的消耗或不可判定原因、各次告警的标识、
检测状态、确认状态及按发生顺序排列的触发/恢复/确认事件;触发与恢复时的
消耗为评估当时记录,不随后续数据变化改写;省略日期范围时展示有告警记录
的全部日期。

导入读数或补录成员版本都不自动评估,显式重评才会更新检测状态;历史查询
只读,不会隐式恢复。批量日期评估要么全部提交要么不提交;创建、评估、
确认任一失败都保留操作前全部状态。读取读数时拒绝全库重复身份(同一设备
同一实际时刻的多条存储记录),包括不属于任何分组的设备。

规则与历史存于数据目录的 `alerts.json`,旧版只含 `device` 字段的设备
规则、告警标识、确认状态与事件顺序无需手工转换即可继续使用。

## CSV 格式

表头固定为 `device,time,reading`,每行一条读数:

- `device`:设备标识,区分大小写,首尾空白忽略,去空白后不能为空
- `time`:秒精度 ISO8601,带 `Z` 或数字时区偏移(如 `+08:00`),必须是真实日期
- `reading`:累计电表读数(kWh),非负,最多三位小数

支持标准双引号字段与 `""` 转义。同一设备同一实际时刻(不同时区偏移
表示同一时刻视为相同)重复且数值相同记为重复并跳过;数值不同视为冲突,
拒绝整批。任一行格式错误同样拒绝整批,不留下部分数据。

## 查询说明

- `--from` 含、`--to` 不含,省略表示不限;起点不早于终点时拒绝查询
- 结果按设备及实际时刻排序;区间由同设备紧邻前驱构成(前驱取自完整
  已存时序,可能在范围之外),区间归属结束时刻
- 无前驱时标明无法计算;累计值下降显示下降异常且不计入汇总
- 时间以 UTC 显示;数值以毫千瓦时 BigInt 精确运算,无浮点尾差,
  不受 Number 安全整数范围限制

## 日报(daily)

`daily` 按 UTC 自然日核查能耗,只读、不写入数据。`--from`(含)与
`--to`(不含)必填且起点必须早于终点;`--device` 可重复指定设备,省略时
统计库内全部设备。日期按 UTC 零点划分,首尾日期只统计与查询范围重叠的
部分。

估算口径:

- 区间由每个设备完整时序的相邻读数构成,两端读数即使在查询范围外也
  参与;范围内没有读数但被有效区间覆盖时仍得到结果
- 非下降区间把累计值之差按持续时间均匀分摊,标为估算:以千分之一 kWh
  为单位,从区间起点累计到切点(查询边界与日界线)向下取整,片段消耗为
  两端累计量之差;完整区间的分摊总量等于原差值,同一区间拆开查询再相加
  结果一致;中间乘积与汇总用 BigInt 精确计算,显示固定三位小数
- 下降区间不分摊消耗,记为异常覆盖;其后的区间仍从下降后的读数计算
- 首条读数之前、末条之后及孤立读数时段为未知,不外推

每天输出估算消耗与有效/异常/未知覆盖秒数,三者之和等于该天实际查询
时长;存在未知或异常覆盖时日报标记为不完整(INCOMPLETE)。没有有效覆盖
时消耗显示无法计算,有效零增长显示零;每台设备汇总已计算的每日消耗。
同设备同一实际时刻存在多条存储记录时报错并返回 1。

## 大数值与旧数据兼容

读数与阈值以毫千瓦时(千分之一 kWh)的 BigInt 表示,解析、求差、分摊、
汇总、比较、保存和显示全程精确,输出固定三位小数,不使用科学计数法。
输入可超出 Number 安全整数范围,例如:

```sh
# 三个 9007199254740.991 kWh 的有效区间合计 27021597764222.973 kWh
node app.ts import big.csv          # reading 列直接写十进制大数即可
node app.ts rule create --id peak --device meter-1 --threshold 9007199254740.990
```

旧版 `readings.json` / `alerts.json` 中以 JSON 数值保存的安全整数读数与
阈值无需手工转换,可直接与新导入的大数值共同计算;新版文件以十进制字符
串保存毫千瓦时。数值型毫千瓦时若已超出安全整数范围(JSON 解析时精度
已丢失),按损坏数据拒绝,不猜测原值。

## 数据位置

`$METERWATCH_DATA_DIR/readings.json`,默认 `~/.meterwatch/readings.json`
(读数与修正历史同文件保存,修正替换与请求成功记录同次原子写入);
告警规则与历史存于同目录的 `alerts.json`,分组配置存于同目录的
`groups.json`,三者相互独立,导入与修正都不会触碰告警状态与分组配置。
退出后再次启动仍可查询。

退出码:0 成功;1 数据或读写错误;2 参数错误。
